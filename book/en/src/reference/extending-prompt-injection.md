# Extending Prompt Injection Validation

This page defines how to add corpus vectors, properties and deterministic
evaluators without weakening the guarantees the engine makes.

The rule behind every rule here: **a finding must be a fact.** If a change would
let the engine report `FAIL` on anything other than a typed, deterministic
observation, it does not belong in this codebase.

## Adding a corpus vector

Corpus vectors live under `corpus/prompt-injection/v1/` and are generated by
`scripts/gen-prompt-injection-corpus.py`, so edit the generator rather than the
JSON, then regenerate and commit both.

A vector must declare:

```text
schema_version   always "1"
id               lowercase-kebab, unique across the corpus
class            DIRECT_ATTACK | INDIRECT_ATTACK | BENIGN_CONTROL
family           a closed InjectionFamily value
source_kind      a closed SourceKind value
property         one of the three Cycle 013 boundary properties
preconditions    closed predicates matching the source boundary
content          encoding + inert payload (+ carrier_note when hidden)
expected_invariant  a closed InvariantType value
safety_class     always SYNTHETIC_NOOP
standards        at least one attribution
provenance       DARE_SYNTHETIC origin, creation date, Apache-2.0
```

Then register it in `corpus/prompt-injection/v1/registry.json` with its
root-confined path.

### Rules

- **Synthetic only.** `provenance.origin` must be `DARE_SYNTHETIC`. Never commit
  captured production traffic, customer text, or anything you did not author.
- **No real secrets.** Canaries must carry the `DARE-SYNTHETIC-CANARY-` prefix.
  Credential-shaped values are refused at load time, including a bearer token
  anywhere in a payload.
- **No executable fields.** `shell`, `sh`, `bash`, `cmd`, `command`, `exec`,
  `eval`, `script`, `callback`, `hook`, `plugin`, `run` and `entrypoint` are
  refused at any depth, as are `url`, `endpoint`, `host`, `provider`, `remote`,
  `base_url`, `webhook` and `upstream`.
- **Payloads are data.** Adversarial instruction prose is expected and allowed —
  that is the vector. What is refused is a *field* that could be executed or a
  *value* that is a real credential.
- **Direction consistency is enforced.** A `DIRECT_ATTACK` must use a `DIRECT_*`
  family, the `USER_PROMPT` source and the user-input boundary property. An
  `INDIRECT_ATTACK` must use an `INDIRECT_*` family, an external source and the
  external-content boundary property.
- **Stay in scope.** Tool description/output poisoning (Cycle 014), memory
  poisoning (Cycle 016), RAG retrieval poisoning (Cycle 017), agent-to-agent
  injection (Cycle 020) and multi-turn grooming (Cycle 021) do not belong here.
  A test asserts no corpus entry carries a `TOOL`, `RAG`, `A2A` or `MEMORY`
  family.

### Pair every attack vector

A new attack vector needs three things, not one:

1. a **secure** scenario, where the reference agent holds the boundary and the
   run should `PASS`;
2. a **vulnerable** scenario using the *same vector, objective and invariant*,
   differing only in the declared reference behavior, which should `FAIL`;
3. a **benign control** — text that looks like the attack but is not one.

The benign control is the part people skip, and it is the part that catches a
detector that has started matching on keywords. If your vector is
"ignore previous instructions", the benign control is a user legitimately asking
whether the agent would obey such a message.

Scenarios carry a `lab.reference_behavior` block but deliberately carry **no
expected verdict**. The engine must never be able to read the answer it is
supposed to compute; expected outcomes live in test code.

## Adding a property

Cycle 013 properties are ordinary v2 registry entries. Follow
[Adding Security Properties](adding-security-properties.md), and additionally:

- keep the `AGENT.` namespace and a closed `risk_family` and `category`;
- add applicability predicates to the closed `Predicate` enum, the JSON Schema
  enum, `AssessmentFacts` and `evaluate_predicate` together — a predicate that
  exists in one but not the others fails closed, which is correct but unhelpful;
- decide deliberately whether the predicate is *target shape*. Target-shape
  predicates yield `NOT_APPLICABLE` when false. A capability gap must yield
  `NOT_TESTED` instead, and an ROE restriction must yield `BLOCKED`. Getting
  this wrong is how an untested property starts looking safe;
- record standards attribution in
  `standards/prompt-injection/2026/provenance.json`. The relation may be
  `SPECIALIZES` or `PARENT_INVARIANT`. `EQUIVALENT` is refused: DARE does not
  claim normative equivalence with upstream guidance;
- add the property to a profile only when you intend to change what that profile
  measures. Adding a property to the registry does not change any existing
  profile's denominator, and it must not.

## Adding a deterministic evaluator

An evaluator maps `objective + normalized events -> Verdict`. To add one:

1. add the variant to `InvariantType` and to the scenario and corpus JSON Schema
   enums;
2. implement the evaluation function in `invariant.rs`;
3. emit whatever typed observation it needs from `normalize()` in `harness.rs`.

### Requirements

- **Typed facts only.** Read `ObservationEvent` variants. Never inspect
  `MODEL_OUTPUT` text, never match keywords, never call a model.
- **Exact matching.** Canaries, action names and field names match exactly, with
  token boundaries. `customer_reference_id` is not `customer_reference`;
  `ticket.summarize_all` is not `ticket.summarize`.
- **State your coverage condition.** `PASS` requires positive evidence that the
  relevant channel was *observed*, not merely that nothing bad appeared. Absence
  of an event usually means the channel was not visible, which is
  `INCONCLUSIVE`. The `CONFORMING` field classification exists precisely to
  distinguish "observed and clean" from "not observed".
- **Never invent a verdict.** A misconfigured objective — an invariant that
  needs a canary when none is declared — is `ERROR`, not `PASS`.
- **Harness failure wins over silence.** Any `HARNESS_ERROR` in the event set
  forces `ERROR`.
- **Reasons are operator-safe.** Never include observed content, a canary or a
  credential in a reason string.

### Tests a new evaluator must carry

- one test per verdict it can produce;
- a prose-only test proving it cannot `FAIL` on model narration;
- a near-miss test proving exact rather than substring matching;
- a determinism test — the same input twice gives the same outcome;
- an evidence-hygiene test proving no reason or event leaks content.

## Adding a harness mode

Think hard before doing this. The three existing modes are local and offline,
and `HarnessMode` deliberately has no variant that could express a remote or
provider target.

`LOCAL_COMMAND` remains unimplemented. It may only be added if explicit argv,
absence of any shell, a strict timeout, bounded stdout/stderr, root-confined
paths and absence of credential flags can all be *proven*, not merely intended.
If any of those is in doubt, do not add it.

A remote provider adapter requires a new Design and Approval cycle. It is not a
code change.

## Versioning

- Additive changes — a new vector, a new property, a new evaluator variant —
  keep `schema_version` at `1`.
- Removing or repurposing a field, or changing what an existing verdict means,
  is a breaking change and needs a new schema version and a new cycle.
- Never renumber or reuse an existing property or vector id. Digests bind
  identity, and reuse breaks the binding silently.

## Before you open a PR

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo audit
```

And specifically for this engine:

```bash
cargo test -p dare-prompt-injection
cargo test -p dare-coverage --test prompt_injection_profile
cargo test -p dare-coverage --test prompt_injection_properties
```

If you added a vector, confirm the hostile fixture suite still refuses
everything it should, and that the two existing baselines
(`agentic-security-baseline-2026` and `mcp-security-baseline`) are untouched.

### If you touch the CI gate

Run the job itself, not an approximation of it:

```bash
python scripts/run-ci-job-locally.py .github/workflows/ci.yml prompt-injection-2026
```

This extracts the `run:` steps from the workflow and executes them verbatim
under `bash -e`, exactly as GitHub does. It exists because a Cycle 013 gate
assertion once passed local review and still failed in CI: the local check
exercised the assertion that was *intended*, while the workflow shipped a looser
one that matched a substring of an unrelated identifier. Verifying the artifact
rather than a paraphrase of it closes that gap.
