# task-037 — Protocol/header/PRM/issuer corpus

**Status:** DONE - REVIEW PASS

Build generated secure/vulnerable paired fixtures for protocol revision, method/name binding, Protected Resource Metadata and issuer/AS boundaries, including benign controls.

## Evidence

Labs 001–010, generated by `scripts/k18/gen_mcp_auth_scenarios.py` and mirrored as corpus vectors by `scripts/k18/gen_mcp_auth_corpus.py`. Each vulnerable lab is a compliant control plus exactly one mutation:

| pair | control | vulnerable | mutation |
| --- | --- | --- | --- |
| revision | 001 | 002 | the server declares a revision the modern authorization surface does not cover |
| method binding | 001 | 003 | routing names a method the body did not request |
| name binding | 001 | 004 | routing names an operation the body did not request |
| resource metadata | 005 | 006 | metadata describing one resource authorizes another |
| AS advertisement | 007 | 008 | the client selects an authorization server the resource never advertised |
| response issuer | 009 | 010 | a well-formed response arrives from an issuer that was never selected |

One mutation function per vulnerable lab is what makes the verdict name a cause rather than a difference. `crates/dare-mcp-auth-security/tests/lab_scenarios.rs` registers all of them.

Both generators are idempotent: `python scripts/k18/gen_mcp_auth_scenarios.py --check` and `gen_mcp_auth_corpus.py --check` reproduce the committed bytes, so a hand-edited fixture is a CI failure rather than silent drift.
